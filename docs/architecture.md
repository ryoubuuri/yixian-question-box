# 第一版实现与研究结论

从前期研究中采用的机制：截图前隐藏自身浮层、显式框选、复用区域、在浮层连续展示答案；题库导入保留题干、选项、答案和来源。竞品服务端排序、模型权重与准确率没有作为本项目已知事实，也未接入其服务。

实际链路：

1. `ScreenCaptureService` 管理本轮 MediaProjection 授权、前台通知、VirtualDisplay 和单帧图像。图像宽高取自实际帧，系统撤销授权后结束会话。
2. `FloatWindow` 隐藏窗口并等待新画面，选择全屏或区域；单次任务以 Job 和会话序号管理，关闭窗口取消待处理结果，结束后释放位图。
3. `QuestionSolver` 用随包 ML Kit 中文 OCR 识别文字和位置；按行粗分题干与选项。该规则不能替代自动版面分析，建议一次框选一道题。
4. `QuestionMatcher` 先比规范化题干，再用双字组 Dice 相似度；近似匹配额外约束数字、英文标识、运算关系和否定词。阈值是初始策略，未经真实大规模题集标定。
5. 有结构化选项时先验证选项正文集合，再把原库正确选项映射为当前字母；重复选项、近似候选冲突均提示核对。旧格式只有答案字母时展示原答案并提示未核对当前选项。
6. 无可靠本地结果时，可调用用户配置的 Chat Completions 服务。AI 不修改导入题库；冲突情况下仅附独立参考。

`BankImporter` 提供 CSV、XLSX、JSONL 入口。`QuestionBank` 以 AtomicFile 保存 JSONL 快照，先验证再替换；导入失败保留旧文件。同题不同答案保留冲突记录。当前所有题目载入内存，匹配全量扫描；不适合把百万题性能作为承诺。

第一版保留上游成熟界面与基础框架，独立包名 `com.yixian.questionbox`。后续优先补题库名称与范围管理、OCR 原文纠错、文本输入搜题、索引、历史与收藏，再扩展自动切题及图像模型。

验证分层：JVM 回归覆盖数字/否定差异、短题干、选项乱序、多选、重复选项、冲突、JSONL 坏行及 CSV 多行；CI 进行 Android 编译和 lint。CI 不能证明真实手机上的悬浮窗权限、OCR 准确率和具体 AI 服务可用性，这些需实机单独验收。
